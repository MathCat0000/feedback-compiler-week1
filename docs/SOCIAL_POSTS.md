## LinkedIn

I built Feedback Compiler for my mother, who receives team feedback as a stream of short messages, notes, requests and deadlines.

The problem is not simply summarising text. It is preserving the difference between:

- what should become an action;
- what has already been decided;
- what is still a conflict or open question;
- which source supports each conclusion.

Feedback Compiler accepts Slack-style threads, email, meeting notes, support tickets, multilingual chat and transcript excerpts, then turns them into a source-linked review board for human approval.

The flow is deliberately conservative:

`different inputs → local compilation → review board → manual handoff`

The first model download needs internet. After that, the main compilation path can stay on the laptop. The handoff controls prepare paste-ready text without signing in or writing to Slack, Linear, Jira, Notion or email.

The local experiment produced valid, source-linked output for all 30 controlled cases and all 8 heterogeneous cases. That is evidence about the tested workflow, not a semantic accuracy guarantee. Manual review remains part of the product.

This project is part of the Hacktoberfest Weekend Challenge: Build for a Friend.
